# CQA Evidence

**Команда Qanagattandirilmagandyktarynizdan**

Локальный прототип оценки качества диалогов. Интерфейс загружает набор, показывает транскрипт и оценку с переходами к доказательствам. Чеклист редактируется через интерфейс. Апелляции сохраняют исходную оценку и пересчитывают итог по использованной версии правил.

## Запуск

Для веб-интерфейса требуется Python 3.10 или новее, FastAPI и Uvicorn. Модель по умолчанию — `gemma3:4b` через локальный Ollama. Оплата за вызовы модельного API отсутствует при локальном запуске.

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
ollama list
cp .env.example .env
```

Убедитесь, что Ollama запущена и выбранная модель доступна. В `.env` задайте `CQA_DATASET_URL` со ссылкой из гайда либо `CQA_DATASET_FILE` с локальным DEV JSON. Через интерфейс можно загрузить JSON вручную. Храните подписанную ссылку и исходные транскрипты локально. Настройка `CQA_DB_PATH` задаёт расположение SQLite.

```sh
set -a
source .env
set +a
python3 -m uvicorn cqa.web:create_app --factory --host 127.0.0.1 --port 8765
```

Откройте [интерфейс](http://127.0.0.1:8765), нажмите «Загрузить набор», выберите диалог и нажмите «Оценить оператора». Нажмите номер реплики в оценке, чтобы увидеть исходный фрагмент. Ссылки на аудио открываются из карточки звонка. Авторизация для локальной демонстрации не требуется.

В «Песочнице» выберите две сохранённые версии и до пяти диалогов. При изменении веса уже полученный ответ пересчитывается. При изменении смысла, шкалы, условий N/A или допустимого доказательства модель получает только изменённые критерии. Апелляции в сравнении не учитываются.

## Командная строка

```sh
python3 -m unittest discover -s tests -v
python3 -m cqa inspect --group DEV --expected-count 65
python3 -m cqa evaluate --dataset data/dev.json --conversation-id p1-ru-001
```

Оценка использует [структурированные ответы Ollama](https://docs.ollama.com/capabilities/structured-outputs). Модель выбирает номера реплик, сервер извлекает исходные цитаты и считает итог. CLI показывает измеренные вызовы, токены и время Ollama. Проверка наличия цитаты не оценивает, насколько она подтверждает вывод.

## Проверка качества

Текущий оценщик использует `gemma3:4b`, версию `cqa-8` и чеклист `official-v1`. Для стандартных критериев модель выбирает один из явных исходов, включая допустимый N/A. Если финальная системная реплика прямо сообщает, что чат закрыл оператор, оценщик заменяет N/A по официальному критерию завершения на «Нет». Критерии, изменённые в редакторе, оцениваются по их сохранённым правилам.

Сравнение с `cqa-6` выполнено на 15 размеченных DEV-диалогах. На шести диалогах, отложенных до настройки, точные совпадения выросли с 27 до 37 из 48 критериев, а средняя абсолютная ошибка итогового балла снизилась с 32,48 до 5,22. В двух настройочных примерах новая версия ошибочно засчитала идентификацию при отсутствии подтверждения личности. Перед сдачей такие решения и достаточность доказательств требуют просмотра по транскрипту.

На отдельной выборке из 12 DEV-чатов `cqa-8` совпал с внутренней разметкой в 70 из 96 решений против 69 из 96 у `cqa-7`. На прежних шести отложенных диалогах результат остался 37 из 48. Разметку составил ассистент по официальному чеклисту. Эти числа описывают внутреннюю проверку на DEV.

## Пакетная сдача

Пакетный режим использует официальный чеклист и исходные AI-оценки. SQLite сохраняет успешные результаты, чтобы повторный запуск мог использовать их из кэша. При технической ошибке в итоговом файле остаётся запись с тем же ID и статусом `error`. Перед публикацией проверьте качество обоснований и отсутствие персональных данных.

```sh
python3 -m cqa batch --split dev --group DEV --team 'Название команды'
python3 -m cqa validate --split dev --group DEV
python3 -m cqa batch --split prod --group "$CONTROL_GROUP" --team 'Название команды'
python3 -m cqa validate --split prod --group "$CONTROL_GROUP"
```

В командах для контроля `CONTROL_GROUP` должен содержать выданный организаторами код группы. Для локального файла добавьте `--dataset путь/к/набору.json`. Результаты по умолчанию записываются в `results/dev/results.json` и `results/prod/results.json`.

## Проверка оценки с готовыми ответами

Передайте JSON-объект с ключами всех восьми критериев из `cqa/official-v1.json`. В каждой записи нужны `value`, `rationale` и доказательство. Доказательство можно указать как массив `evidence` с полями `turn` и `quote` либо как диапазон `checked_turns` из двух включительных границ. Все позиции начинаются с 1 и соответствуют исходному массиву, включая бота, клиента и системные сообщения.

Ниже один элемент объекта ответов.

```json
{
  "contact": {
    "value": true,
    "rationale": "Оператор поздоровался и представился в первом ответе.",
    "evidence": [{"turn": 4, "quote": "Добрый день! Меня зовут Дана."}]
  }
}
```

Остальные семь элементов заполняются по тому же контракту. `null` разрешён только для критериев с условием N/A. Утилита проверяет типы, ступени шкалы и наличие цитат. Смысловую применимость N/A и достаточность доказательства на этом этапе проверяет человек.

```sh
python3 -m cqa score --dataset data/dev.json --conversation-id p1-ru-001 --answers data/answers.json
```

Команда печатает отдельную запись с `conversation_id`, `status`, `criteria` и `score`. При ровно половине сотой используется округление вверх, поскольку материалы задают точность до двух знаков без отдельного правила для равенства.
